# @artiflow/web

The Artiflow website: the landing page at <https://artiflow.dev> and the documentation, built
with Astro and Starlight, at <https://artiflow.dev/docs>.

The landing is a plain Astro page at the domain root, `src/pages/index.astro`. Docs are
mounted at `/docs` by their content directory, and the Starlight config sets no global Astro
`base`.

## Setup

The workspace is part of `bun install` at the repository root; there is nothing
to install here. Astro's CLI runs on Node.js 24, the declared runtime
(`engines` in `package.json`).

```sh
bun install          # once, at the repository root
bun run web:dev      # http://127.0.0.1:4321/docs/
bun run web:check    # astro check (types and content)
bun run web:build    # static site in apps/web/dist
bun run web:verify   # check, build, then verify links and configuration parity
```

The same commands work from this directory with `bun run dev`, `bun run check`,
`bun run build` and `bun run verify`. `bun run web:preview` is not defined at the
root; use `bun run --filter '@artiflow/web' preview` to serve a built site
locally.

## Layout

| Path                          | What it holds                                                                          |
| ----------------------------- | -------------------------------------------------------------------------------------- |
| `astro.config.mjs`            | Site URL, Starlight options, the labelled sidebar groups, autogenerated per directory. |
| `src/content.config.ts`       | The `docs` collection (`docsLoader`, `docsSchema`).                                    |
| `src/content/docs/docs/**`    | Pages. A file here becomes a route under `/docs/`.                                     |
| `src/pages/index.astro`       | The landing page at `/`.                                                               |
| `src/components/`             | Landing pieces: wordmark, symbol, agent logos and the artifact-kind tabs.              |
| `src/styles/site.css`         | Fonts plus the palette tokens imported from `apps/dashboard/src/styles/tokens.css`.    |
| `scripts/check-built.mjs`     | Built-output verifier: links, assets and fragments.                                    |
| `scripts/check-reference.mjs` | Configuration verifier: source env names against the reference.                        |
| `src/styles/docs.css`         | Starlight's `--sl-*` colors mapped onto the shared tokens.                             |
| `src/assets/`, `public/`      | The wordmark for light and dark, and the favicon.                                      |

## Output

`web:build` writes a static site to `apps/web/dist`: HTML, CSS, JS and the
Pagefind search index. Starlight's search is native and prebuilt, and the site
needs no adapter, no server runtime and no deploy target. Publish `dist/` behind
whatever serves `artiflow.dev`, with `/docs/` as its base path.

Adding a page needs no configuration change: create the file under
`src/content/docs/docs/` and it appears under its section's sidebar group. Do not
document functionality the code does not support, and do not link pages that do
not exist yet.

## Verify the built site

`bun run web:verify` runs `web:check`, then `web:build`, then both verifiers in
order. Only the verifiers read files the build produced or must stay in sync with:

| Command                                   | Verifies                                              |
| ----------------------------------------- | ----------------------------------------------------- |
| `bun run web:verify`                      | `astro check`, the build, then both commands below.   |
| `node scripts/check-built.mjs`            | An existing `apps/web/dist` (no build).               |
| `node scripts/check-built.mjs <distDir>`  | Another build directory, such as a CI artifact.       |
| `node scripts/check-reference.mjs`        | `config.ts` against the configuration reference.      |
| `node scripts/check-built.mjs --help`     | Arguments, checks and exit codes of the link check.   |
| `node scripts/check-reference.mjs --help` | Arguments, checks and exit codes of the parity check. |

`check-built.mjs` resolves every local `href` and `src` in the built HTML:
absolute routes, relative routes, assets, same-origin `https://artiflow.dev/...`
URLs, same-page `#fragment` and query-only `?theme=dark#fragment` links,
and cross-page fragments. URLs from other origins and special
schemes (`http`, `https`, `mailto`, `tel`, `data`, `javascript`,
protocol-relative) are skipped, and nothing is written to `dist/`.

`check-reference.mjs` compares the environment names read in
`apps/api/src/config.ts` with the "API process variables" section of
`src/content/docs/docs/reference/configuration.md` in both directions, so an
undocumented variable and a stale row both fail. Its `--root <dir>` option
resolves both files from another checkout and exists for the fixture tests in
`test/web-reference.test.ts`.

Both commands use the same exit codes: `0` clean, `1` problems found, `2` usage
error or unreadable input.

Deliberate adaptations, all driven by Artiflow's needs rather than preference:

- **Astro + Starlight instead of SolidStart.** The future root site at
  `artiflow.dev` will be Astro, so the docs share that toolchain and the website
  can mount them without a second framework.
- **One English locale.** The product and repository are English; there are no
  machine-generated translations and no locale routes pretending otherwise.
- **Native sidebar, table of contents and search.** Starlight generates all
  three from this content, replacing the hand-written navigation and the
  separately wired Pagefind build.
- **No reused assets, text or brand.** Only the documentation shape was studied:
  Artiflow uses its own palette, logo, copy and section layout
  (`start`, `connect`, `concepts`, `artifacts`, `guides`, `self-hosting`,
  `contributing`).
